# 🚀 Sber-AmazMe-FMLib - библиотека для разработки и продуктизации FM моделей на платформе AmazMe.

Библиотека разработана таким образом, чтобы быть быстрой и простой в использовании как при проведении экспериментов, так и выводе моделей в ПРОМ контур Банка. Вы можете обучать, дообучать и проводить инференс моделей. Код библиотеки, написанный для проведения экспериментов, __не отличается__ от кода в ПРОМ контуре Банка.

Библиотека содержит готовые к использованию [модели юнита Data](#supported-models). Ключевые акценты при разработке библиотеки делались на __модульности__, __простоте__ и __скорости__ вывода моделей в ПРОМ.

Код библиотеки доступен в [Sigma](https://stash.delta.sbrf.ru/projects/AMAZMEFM/repos/sber-amazme-fmlib/browse) и [Omega](https://df-bitbucket.ca.sbrf.ru/projects/AMAZMEFM/repos/sber-amazme-fmlib/browse).

## 🧱 Основные структурные блоки

### Работа с данными
ETL для тренировки FM-моделей предполагает обработку большого объема данных. Объем данных настолько большой, что поместить их полностью в оперативную память не представляется возможным. Поэтому мы рекомендуем выполнять обработку данных с использованием `PySpark` в кластерном режиме.

Библиотека предназначена для тренировки и инференса моделей с помощью `PyTorch`, поэтому мы пользуемся парадигмой побатчевой обработки данных.
Подразумевается, что тяжеловесный препроцессинг данных выполнен перед запуском тренировки/инференса модели. На стороне библиотеки существует специфичная для каждой модели обработка данных (например, создание `padding_mask`, `attention_mask` и т.д.) - подобные операции эффективнее выполняются в побатчевом режиме.

Подробное описание по работе с данными внутри библиотеки можно найти [здесь](docs/data_processing.md).


### Конфигурации 
В целях достижения максимальной гибкости и минимизации изменения кода для инициализации объектов мы используем фреймворк `Hydra`. `Hydra` позволяет указать всё необходимое для тренировки/инференса через обычный `yaml`-файл. Примеры конфигов можно найти [здесь](examples/configs/).

**Примечание**: для создания конфига новой модели нет необходимости создавать его с нуля. Вы можете переиспользовать существующий, в большинстве случаев вам потребуется поменять путь до тренировочного датасета, путь до валидационнго датасета, модель и путь для сохранения чекпоинта модели.


### Модель
Самым эффективным способом на текущий момент является концептуальное разделение модели на "тело" и голову". "Тело" предназначено для генерации эмбеддингов (скрытых состояний) пользователей и подачи их в "голову". "Голова" предназначена для решения конкетной задачи, это может быть классификация, регрессия или предсказание вероятности взаимодействия клиента по тому или иному каналу коммуникации (uplift).

#### Существует несколько вариантов тренировки моделей:
1. Претрейн (pretrain) "тела" для того, чтобы модель поняла общие сведения о представлении мира банковских взаимодействий. Файнтюн (finetune) "головы" для решения конкретной банковской задачи.

    ```
    Body pretrain --> Head finetune
    ```

2. Претрейн (pretrain) "тела" для того, чтобы модель поняла общие сведения о представлении мира банковских взаимодействий. Файнтюн (finetune) "тела" для того, чтобы модель сформировала свою экспертизу в конкретной области. Файнтюн (finetune) "головы" для решения конкретной банковской задачи.

    ```
    Body pretrain --> Body finetune --> Head finetune
    ```
Реализация существующих моделей создана таким образом, что вы можете изменять её структурные блоки (например, изменить модуль вычисления `Attention` или поменять `Encoder`), но архитектуру модели (последовательности применения операций) вы изменить не сможете.

Ознакомиться с реализацией моделей можно [здесь](fmlib/nn/models/).

<a name="FAQ"></a>
## ❓ Часто задаваемые вопросы

### Я хочу натренировать голову модели под конкретную задачу. Что мне делать?
1. Найдите чекпоинт модели-тела и подготовьте конфигурацию для получения эмбеддингов (скрытых состояний). Чекпоинт модели можно получить напрямую от авторов модели или разработчики библиотеки могут подсказать где его найти. Список разработчиков можно найти в [pyproject.toml](pyproject.toml) в разделе `authors`.
2. (Опционально) Запустите инференс тела с помощью FMLib для получения эмбеддингов.
    
    1. Установите библиотеку, используя [гайд по установке](docs/installation.md)
    2. Подготовьте конфигурацию для запуска инференса. Пример конфигурации для [SequenceRepresentation 2M](examples/configs/inference/sequence_representation_2M)
    3. Запустите инференс. [Пример запуска инференса из Jupyter-ноутбука для модели `SequenceRepresentation`](examples/sequence_representation_inference.ipynb)
    4. Полученные скрытые состояния объедините с фичами, которые требуются для обучения головы. Для этого нет функционала в библиотеке, но вы можете воспользоваться функцией `join` в `PySpark.DataFrame`.
3. Запустите тренировку головы. [Пример для модели `FeatureTransformer`](examples/feature_transformer_training.ipynb). [Пример запуска тренировки на кластере HGX](examples/HGX/sequence_representation_training.ipynb).

    Пример конфига для модели [`UpliftFeatureTransformer`](examples/configs/train/uplift_feature_transformer.yaml) и [`FeatureTransformer`](examples/configs/train/feature_transformer.yaml). В этих конфигах достаточно изменить следующие значения:
    - `training_data.source` - путь до тренировочных данных
    - `validation_data.source` - путь до валидационных данных
    - `epoch_callbacks.callbacks.SaveCheckpointCallback.base_path` - путь для сохранения лучших чекпоинтов модели

4. Запустите инференс натренированный головы. [Пример для модели `FeatureTransformer`](examples/feature_transformer_inference.ipynb)

### Я разработал новую FM модель. Как мне её добавить в библиотеку?
1. Разбейте модель на структурные блоки (например, `Embedding` слой, `Encoder`, `Decoder`, `Attention`, `FeedForwardNetwork` и тд).
2. Ознакомьтесь с существующими реализациями моделей и блоков внутри библиотеки. Возможно, в вашей модели можно что-то переиспользовать из существующего функционала.
3. Подготовьте реализацию модели и конфигурацию для её тренировки и инференса.
4. Проведите тестирование модели, пилоты и опубликуйте метрики на [leaderboard команды CDS](https://df-bitbucket.ca.sbrf.ru/projects/DSRPT/repos/experiment_results/browse). Leaderboard предназначен для объективного сравнения моделей.
5. Подготовьте Merge Request согласно [рекомендациям по разработке](CONTRIBUTING.md) и свяжитесь с одним из разработчиков библиотеки для прохождения ревью. Список разработчиков можно найти в [pyproject.toml](pyproject.toml) в разделе `authors`.
6. После успешного залития Merge Request в `master`-ветку происходит планирование релиза. Планирование релиза заключается в определении даты выхода релиза (доступ пакета в Nexus) и какие изменения войдут в релиз. Описание процесса [версионирования](CONTRIBUTING.md#versioning) и [релиза](CONTRIBUTING.md#release-process).
