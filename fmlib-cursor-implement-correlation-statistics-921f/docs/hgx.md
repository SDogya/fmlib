# 🥏 Обучение и инференс на кластере HGX

Использование кластера HGX необходимо, когда вам не хватает ресурсов в Datalab AI (максимум можно взять 2 GPU). Кластер предоставляет возможность использования нескольких GPU нод, 1 нода содержит 4 GPU A100 80Gb. Количество доступных вам нод определяется командными доступами.

## Основные понятия
  - `HGX` - название кластера, на котором можно осуществлять обучение и инференс. Реализует очередь из запросов к ресурсам т.н. тасок.
  - `Osiris` - библиотека Python, реализующая доступ к очереди на суперкомпьютер.

    **Примечание:** Osiris может быть добавлен в окружение следующим образом:
    ```python
    import sys
    import os
  
    sys.path.insert(0, os.path.abspath("/opt/clients"))
  
    import osiris
    ```

## Алгоритм работы

1. [Получите доступ к кластеру](access.md#hgx).
2. Для работы с HGX необходимо использовать виртуальное окружение. Вы можете установить [неизменяемую версию библиотеки из источника](installation.md#source-installation) или [из Nexus](installation.md#nexus-installation).
3. Кластер поддерживает работу **только** с данными на NFS. Перед запуском убедитесь, что все данные находятся на NFS.

    Скопировать данные из HDFS на NFS можно с использованием команды `get`:
    ```bash
    hadoop fs -get hdfs://arnsdpsbx/user/team/team_ai_avatar/avatar_fm/examples/next_event_prediction/processed_sequences \
    /home/datalab/nfs/osiris_body_training_data/
    ```

4. Убедитесь, что тренировка запускается локально с использованием 1 или 2 GPU. В идеале дождаться завершения первой эпохи, чтобы убедиться в работоспособности валидации. Если вы используете объёмный тренировочный датасет, то вы можете сделать тестовый запуск на, например, одной партиции этого датасета.

5. Создание таски и отправка на HGX

    Создайте свой скрипт по примеру:
    - [Примеру обучения головы FM CDS](../examples/osiris_body_training.ipynb)
    - Официальным примерам использования HGX (`~/examples/training/pytorchjob-advanced.ipynb`)


### Примерный список параметров обучения на кластере HGX:
- `name` - название таски, должно быть дескриптивным и уникальным. В дальнейшем вы будете обращаться к Osiris по нему.
- `image` - образ контейнера Kubernetes в котором будут запущены Ваши скрипты на кластере.
- `restart` - флаг, определяющий будет ли перезапущена таска в случае падения по вине самого кластера. Рекомендуется значение `False`.
- `pool` - пул машин. Для нас доступен только `public`.
- `command` - какой исполняемый файл будет запущен. Это обязан быть `accelerate` из созданного виртуального окружения. Пример пути до исполняемого файла - `/home/datalab/nfs/venv/bin/accelerate`.
- `args` - аргументы конфигурации запуска.
- `num_gpus`, `num_nodes` - количество GPU на каждой ноде и количество самих нод.

    **Примечание:** Количество нод долно быть согласовано, а количество процессов должно быть равным `num_processes = num_gpus * num_nodes`.

    **Примечание:** `num_gpus` должно быть кратно 4.
    
    **Примечание:** термин, отвечающий за количество процессов внутри библиотеки называется `num_replicas`.
