# 📜📃📄 Работа с данными в Sber-AmazMe-FMLib


## 🎨 Дизайн
Одной из уникальных особенностей библиотеки является работа с данными. Мы исходим из того, что вся "тяжеловесная" подготовка данных (ETL) были выполнены с помощью `PySpark` и в качестве входных данных в модель мы имеем `parquet`-файлы.

## 🧩 Концепты
Для максимально эффективной загрузки данных из `parquet` в видеопамять мы используем абстракцию `ParquetDataset` вместо привычного всем `torch.utils.data.DataLoader`.
Эта абстракция позволяет загружать в память только батчи заданного размера.
В результате работы этой абстракции вы получаете словарь, ключи которого являются названиями столбцов, а значения - это `torch.Tensor` данных из столбца.
Абстракция поддерживает работу только с целыми и вещественными числами, вы не можете подать строки или более сложные структуры.
После получения батча данных вы можете сразу подать их в модель, но в большинстве случаев требуются дополнительные преобразования. Эти преобразования внутри библиотеки называются `Transform`.

Примеры `Transform` операций:
- переименование ключей
- создание новых тензоров на основе существующих:
    - объединение тензоров
    - создание `attention_mask`
    - определение года, високосности года, месяца года, дней недели, дней года, часов, минут на основе пришедшего `timestamp`
    - изменение паддинга с левого на правый
- добавление новой информации в батч (например, канал коммуникации для задач Campaigning)

С нашей стороны было проверено и доказано, что операции подобного рода быстрее выполняются на `GPU`, чем на `PySpark`.

## Дополнительные особенности `ParquetDataset`:
- вы можете загружать данные не только с локального диска, но и с S3 или HDFS. Для этого достаточно указать `filesystem` и корретный путь до данных. 

    **Примечание:** если вы тренируете модель, используя данные в удаленной файловой системе, то это будет медленнее, чем при тренировке с локальной файловой системой из-за передачи данных по сети. Поэтому, если у вас есть возможность скопировать данные на локальное хранилище, то сделайте это.
- Указывайте `partition_size` как можно больше, основываясь на размере доступной видеопамяти. В документации `PyArrow` рекомендуется использовать значение `2^17 = 131_072`. Сначала прочитается партиция заданного размера и затем она будет разбиваться на батчи размера `batch_size`.
- Перемешивание порядка строк включается при указании параметра `generator`. Если параметр `generator` не указать, то порядок строк будет соответствовать порядку в `parquet`-файлах. Перемешивание строк работает только внутри одной партиции. Порядок считываемых партиций будет всегда одинаковый. Поэтому для более качественного перемешивания указывайте большой `partition_size`.
- Поддерживает работу в MultiGPU режиме
